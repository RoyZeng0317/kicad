## 1. ERC（電路圖電氣規則檢查）結果

**總計：124 個違規（102 錯誤 / 22 警告）**

### 1-1 高風險（會導致 Mega2560 無法正常開機/運作）

| 問題 | 位置 | 影響 |
|---|---|---|
| `power_pin_not_driven` | U1 Pin 10 `VCC`、Pin 100 `AVCC` | **主控 MCU 的核心供電腳與類比供電腳沒有被任何電源符號驅動** → 電路圖上等同「沒接電源」，即使 PCB 有走線，圖面本身邏輯不完整，之後改圖容易出錯 |
| `pin_not_driven` | U1 Pin 34 `XTAL1` | 16MHz 石英振盪器的驅動關係未在圖上正確標示，需確認 Y1 迴路（XTAL1/XTAL2 + 2 顆負載電容 + GND）在圖面上是真正的網路連接，而不是只靠 label 巧合同名 |
| `power_pin_not_driven` | #PWR01, #PWR017, #PWR08 | 多個電源符號本身是「輸入」，卻沒有對應的「輸出」電源符號（如 +5V/+3V3 標誌）在同一網路上，電源樹沒有真正的來源 |
| `undefined_netclass` (Net Class 8 / Net Class 4) | Directive Label | 圖上放了「指定網路類別」標籤，但該網路類別在專案設定裡**沒有定義** → 這些網段實際上會落回 Default 類別（線寬 0.2mm），失去原本想要的差異化設計 |

### 1-2 中風險（功能缺陷，暫不致命但要修）

- U2、U4（LMV358 雙運放）：只放置了單元 A，**單元 B/C（含電源腳）完全沒有放到圖上**（`missing_unit`, `missing_power_pin`）。這代表運放的電源腳並未被規劃，實際 PCB 上該 IC 若真的通電但輸入浮接，可能造成輸出異常（不至於燒毀，但功能不可靠）。
- U1 有多達 20+ 個 GPIO（PJ2-PJ7、PH2、PH7、PG3/PG4、PD3-PD6、PE2/PE6/PE7 等）完全未連接 — 若這些是刻意保留未使用是可以接受的，但需要你確認「哪些是有意保留、哪些其實漏接」。
- U6 全腳未連接（見上方 0. 專案組成說明）。
- USB 子圖 `/USB/` 內 P1（USB 接頭）VBUS/D+/D-/VCONN 及 U5 多個腳位未連接、UVCC/UGND 電源腳未驅動。

### 1-3 低風險（警告/命名/庫問題，不影響電性）

- `mc33269_sym`、`mh2029-300y`、`MF-MSMF050` 三個符號庫在目前設定中找不到（庫路徑問題，開圖時可能出現找不到符號的警告，但不影響已放置元件的電性）
- 幾個 Label 只接到單一腳位（`isolated_pin_label`，例如 `3V3`, `XTL1`, `XTL2`, `AVCC`, `TXD1`, `USBVCC`, `PE0`, `PE1`, `RESET`）→ 這通常代表**這條網路只是「看起來」有名字，實際上沒有連到對側**，值得逐一核對
- `+3v3` label 與 `#PWR017`（大寫 `+3V3`）大小寫不同判定為相似但不同網路 → 有機率造成 3.3V 電源被誤判成兩條不同的網，其中一條沒被驅動（這點與 1-1 的 #PWR017 問題是同一個根因）

## 2. DRC（PCB 設計規則檢查）結果

**總計：90 個違規 ＋ 175 個「未連接」項目（ratsnest 仍然開路）**

### 2-1 致命：板框缺失
```
[invalid_outline] 電路板的邊框有錯誤（在 Edge.Cuts 層上找不到邊框）
```
目前 PCB **沒有合法封閉的板框（Edge.Cuts）**。這會影響：
- 無法正確產生 Gerber 外形檔給板廠
- 銅箔鋪銅（zone fill）若有以板框為邊界的設計，鋪銅範圍會不正確或直接鋪滿到座標原點

### 2-2 致命：大量網路實際上沒有連通（175 項）
DRC 顯示的「未連接」不是單純警告，而是同一個網路（例如 `+5V`、`GND`、`/RESET`、`/XTAL1`、`/XTAL2`、`/SDA`、`/SCL`、`/VIN`…）在板子上**存在多段各自獨立的銅箔／焊盤，彼此之間沒有被走線或鋪銅實際連起來**。舉例：

- `+5V`：U5 Pad32、R2、C4/C5/C6/CPC1、RN1B/RN1C/RN3A/RN5A、XIO1、J2、U3、D3、IC1、J7/J8… 分成一大堆孤立小群，沒有串成一條完整的 +5V 銅箔
- `GND`：U1 多個 GND 腳彼此之間、U5 的 GND、C1-C11 的 GND 端、RN5D、XIO1 等，同樣是斷成多段
- `/RESET`、`/XTAL1`、`/XTAL2`：Mega2560 開機與時脈相關的關鍵網路也在「斷路」名單中

**這代表目前這塊板子如果直接送去打樣、焊接元件，Mega2560 大機率無法開機或無法穩定運作**（電源沒有完整送到、重置電路不完整、振盪迴路不完整）。這是本專案要達成「01. Mega2560 可以正常使用」之前，**優先權最高**的一類問題，且是舖銅／補線可以直接解決的。

### 2-3 局部間距違規（USB 接頭 P1）
USB-C 接頭 P1 的相鄰 pad 間距實際只有 0.12～0.1315mm，但目前規則要求 0.2mm（12 處），皆標記為「Local override」— 也就是這個 footprint 原廠可能已針對這顆料號設定了局部間距例外，但仍建議之後生產前跟板廠 (PCB 廠) 的實際製程能力（一般 6mil/0.15mm 為主流下限）核對一次，避免短路風險。

### 2-4 絲印相關（純外觀，不影響電性）
- 大量 `silk_overlap`（元件參考編號互相重疊）與 `silk_over_copper`（文字壓到焊盤）
- 文字高度/線寬低於板規設定值（0.05mm vs 要求 0.08mm 最小線寬；0.70mm vs 要求 0.8mm 最小高度）

這類問題只影響可讀性（例如組裝時看零件編號），**不會造成 IC 燒毀**，優先權最低，可留到最後美化階段處理。

## 3. 線寬／電流安全性初步計算（對應你的需求 04）

### 3-1 目前設計規則
專案目前**只有一個網路類別「Default」**：
- Track width（線寬）：**0.2 mm**（約 7.87 mil）
- Clearance（間距）：0.2 mm
- Via 直徑：0.6 mm

也就是說，**電源線（+5V／VIN／GND）目前跟一般訊號線用同樣的 0.2mm 線寬**，並沒有針對大電流網路做加寬處理，也沒有另外設定 Power 類別。銅厚假設為 KiCad 預設 1oz（35µm）— 這點需要你確認板廠實際下單的銅厚，若非 1oz 以下計算需要重算。

### 3-2 IPC-2221 電流承載能力估算（外層銅箔，1oz / 35µm）

公式：`I = k × ΔT^0.44 × (W × T)^0.725`
（k=0.048 外層；ΔT 為溫升；W、T 為線寬、銅厚，單位 mil）

| 線寬 | 溫升 10°C 可承受電流 | 溫升 20°C 可承受電流 |
|---|---|---|
| 0.2 mm（目前 Default） | **約 0.74 A** | **約 1.0 A** |
| 0.5 mm（建議電源線最小值） | 約 1.5 A | 約 2.1 A |
| 0.8 mm（建議 VIN/+5V 主幹） | 約 2.1 A | 約 2.9 A |

### 3-3 這代表什麼風險？

- Arduino Mega2560 本身（僅 MCU + 週邊 LED/按鍵）典型消耗電流通常在 100～300mA 左右，**單純線寬 0.2mm 理論上還撐得住**，不至於讓走線本身過熱燒斷。
- 但本板額外整合了 USB 轉序列晶片（U5）、穩壓 IC（IC1/IC2, LP2985-3.3、LD11117S50 等）、多組排針（可能是要外接模組/馬達/繼電器等負載）。**只要外接負載的合計電流超過約 0.7～1A**，0.2mm 的 +5V/VIN 主幹走線就會出現明顯溫升與壓降，長時間下可能造成：
  1. 走線局部過熱、銅箔氧化甚至燒起泡（極端過載時）
  2. 供電壓降過大，導致 U1（ATmega2560）在瞬間大電流負載（如馬達啟動）時 VCC 掉到規格下限，引發**重置異常/資料損毀**，而不是「燒毀」本身
  3. 穩壓 IC（LDO）本身若因外部負載超出其額定電流（例如 LD1117 系列多為 800mA-1A），**LDO 過熱保護或直接燒毀**的風險比走線本身更高，需要另外核對 IC1/IC2 的實際負載
- 目前**尚未看到穩壓 IC 的散熱與電流餘裕評估**，也尚未確認整板實際負載電流，這是下一輪需要跟你確認的重點（見第 5 節）。

> 結論：以目前「0.2mm 走線 + 無獨立電源網路類別」的設計規則來看，**還不到會直接把 IC 燒毀的程度**，但屬於「電源設計餘裕不足」，且因為 2-2 節的斷路問題，目前這塊板子連通電開機都做不到，電流計算要等連通性修好後才有意義。

## 6. 學習筆記（對應你的需求 10/11）

這是我在這次 Round 0 分析中學到、之後會持續沿用的方法論：

1. **先跑 ERC/DRC 再看圖**：電路圖看起來「線都畫好了」不代表電氣連通，`power_pin_not_driven`、`pin_not_driven` 這類錯誤專門抓「圖面上看似有名字但邏輯上沒有真正驅動來源」的網路。
2. **DRC 的「未連接」不是佈線美觀問題，是真的斷路**：PCB 上即使目視有銅箔在附近，只要 ratsnest 沒消失就代表電氣上不通，這是本專案目前最大的功能性風險來源。
3. **線寬安全性要用 IPC-2221 換算，不能憑感覺**：`I = k × ΔT^0.44 × (W×T)^0.725`，同一塊板子的訊號線與電源線應該分開網路類別（Net Class），電源/大電流網路需要單獨加寬，而不是全部套用同一個 Default 線寬。
4. **是否燒毀 IC 要分兩層看**：走線本身過熱燒斷 vs. 穩壓 IC/晶片因超出額定電流而過熱燒毀，兩者的計算依據不同（前者看 IPC-2221 銅箔載流能力，後者要看該顆 IC 的 datasheet 額定電流與散熱設計）。
5. **kicad-cli 可以在不開 GUI 的情況下**跑 ERC (`sch erc`)、DRC (`pcb drc`)、匯出 SVG (`sch export svg` / `pcb export svg`)，非常適合這種「每次修改都要留存證據給你看」的流程。
